# Проект по базам данных: потребительское кредитование (Home Credit)

Групповая работа по дисциплине «Базы данных». Проектирование и реализация БД на PostgreSQL по датасету Home Credit Default Risk: от карты данных и нормализации до физической реализации, аналитических запросов и программного доступа.

## 1. Датасет (этап 0)

**Название:** Home Credit Default Risk.
**Источник:** Kaggle, https://www.kaggle.com/c/home-credit-default-risk (для скачивания нужна учётная запись Kaggle и принятие правил соревнования).
**Предметная область:** потребительское кредитование и кредитный скоринг. Датасет описывает заявки на кредиты, кредитную историю клиентов (внутреннюю и из кредитных бюро) и платежи по прошлым кредитам.

**Объём.** В сумме датасет содержит более 50 млн строк (требование задания: не менее миллиона):

| Файл | Содержание | Строк (примерно) |
|------|------------|------------------|
| `application_train.csv` | текущие заявки с целевой переменной `TARGET` | 307 тыс. |
| `application_test.csv` | текущие заявки без `TARGET` | 49 тыс. |
| `bureau.csv` | кредиты клиентов в других организациях | 1,7 млн |
| `bureau_balance.csv` | ежемесячные статусы кредитов бюро | 27 млн |
| `previous_application.csv` | прошлые заявки клиентов в Home Credit | 1,7 млн |
| `POS_CASH_balance.csv` | ежемесячные балансы POS и cash кредитов | 10 млн |
| `credit_card_balance.csv` | ежемесячные балансы кредитных карт | 3,8 млн |
| `installments_payments.csv` | платежи по прошлым кредитам | 13,6 млн |
| `HomeCredit_columns_description.csv` | описание столбцов (кодировка `latin-1`) | |

**Какие файлы используются в проекте.** `application_train`, `previous_application`, `bureau`, `installments_payments` (подвыборка). Остальные файлы (`bureau_balance`, `POS_CASH_balance`, `credit_card_balance`, `application_test`) в схему не входят, чтобы удержать объём проекта.

**Синтетические данные.** В датасете нет выручки и прибыли клиентов, договоров, залога, поручителей и персональных данных, поэтому они генерируются отдельно (Faker, формулы от реальных полей). Правила и seed: `docs/synthetic_data.md`.

## 2. Как получить данные

Полные CSV в репозиторий не входят (размер около 2,7 ГБ, GitHub не принимает файлы больше 100 МБ).

1. Скачать архив с Kaggle (ссылка выше).
2. Распаковать CSV в папку `data/raw/` (она в `.gitignore`).
3. Для проверки структуры в репозитории лежат сэмплы по 5 строк: `data/samples/`.

## 4. Схема БД

13 таблиц, 5 групп:

| Группа | Таблицы |
|--------|---------|
| Клиент | `client`, `client_personal`, `client_financials` |
| Заявка и договор | `application`, `application_housing`, `loan_contract`, `collateral`, `guarantor` |
| Кредитная история | `previous_application`, `bureau` |
| Платежи | `installments_payments` |
| Служебные | `audit_log`, `ref_dictionary` (единый справочник категорий) |

Основные решения:
- Персональные данные (ФИО, паспорт, контакты, адрес) вынесены в отдельные таблицы `client_personal` и `guarantor` для разграничения доступа по 152-ФЗ.
- Категориальные значения (образование, семейное положение, тип договора и др.) хранятся в `ref_dictionary`.
- Нормализация доведена до 3НФ. Подробно: `docs/analysis/tables_overview.md`.

ER-диаграмма: `docs/diagrams/er_diagram.png`.
